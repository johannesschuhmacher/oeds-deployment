## Issue Found And Fixed

The first isolated DB init test showed that `open-data` became healthy while
the expected init artifacts were missing:

- `readonly` role
- `postgis` extension
- `public.linear_interpolate` function

Container logs showed that the copied KIT shell script was bind-mounted with
Windows CRLF line endings and failed as `bash\r`.

Fix:

- Added `modules/oeds-deployment/modular_initdb/09-bootstrap-roles.sh` with LF
  line endings.
- Updated `compose.modular.yml` to mount that LF-only script.
- Kept the copied KIT file unchanged so byte parity remains valid.
- Added `tools/test_db_smoke.ps1` to make this regression test repeatable.

The first real crawler post-run test also showed that legacy Python post-run
scripts could not import workspace modules such as `crawler_core` when executed
as `python scripts/...py`.

Fix:

- Scheduler post-run subprocesses now prepend the workspace CWD to
  `PYTHONPATH`.
- Added a scheduler unit test that covers legacy script imports from the
  workspace root.
- `Dockerfile.crawler-modular` now sets `PYTHONPATH=/app` for installed
  console scripts.

The first full stack smoke showed that the Admin UI resolved its repository
root to the installed package path instead of the runtime workspace.

Fix:

- Admin config root resolution now prefers `OEDS_ADMIN_REPO_ROOT`, then the
  current runtime workspace, then `/app`, then the package fallback.
- `compose.modular.yml` sets `OEDS_ADMIN_REPO_ROOT=/app` for `crawler-admin`.
- Added a stack smoke that verifies Admin UI, PostGREST, and Grafana over HTTP.

## Remaining Gaps

This run proves the active local crawler set in addition to the SMARD post-run
path: ENTSO-E API, ENTSO-E FMS EnergyPrices, power-system data, and weather
forecast all wrote rows to the disposable DB. It does not yet prove every
optional disabled crawler, especially PRISMA, GIE, Copernicus CDS, EIA,
Netztransparenz, EPEX SFTP, or large public download crawlers. The Ansible
remote-host install path is copied and structurally checked, but not yet
executed on a remote test host.
