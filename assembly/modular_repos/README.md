# Modular OEDS Workspace

This directory is generated by `oeds-deployment/tools/assemble_workspace.py`.
The official Open Energy Data Server remains the base; independent add-on
repositories provide the KIT extensions.

## Components

| Path | Responsibility |
| --- | --- |
| `sources/oeds-core` | pinned checkout of the official OEDS repository |
| `modules/oeds-crawler-pack` | 21 KIT crawler implementations and temporary BaseCrawler adapter |
| `modules/oeds-scheduler-ui` | scheduler runtime and crawler admin UI |
| `modules/oeds-post-scripts` | gapfill, backfill, forecast, and derived-data tools |
| `modules/oeds-deployment` | installation, Compose, Ansible, operations, and compatible version pins |

The old `open-energy-data-server-KIT` repository is not part of an assembled
workspace. Its functions have module owners instead of being copied into the
workspace root.

## Verification

From the workspace root:

```powershell
python .\modular_repos\tools\verify_modules.py
python .\modular_repos\modules\oeds-deployment\tools\verify_deployment.py
docker compose --profile crawlers `
  -f .\modular_repos\modules\oeds-deployment\compose.yml config --quiet
```

The verifier checks registry priority, scheduler contracts, stable post
commands, component files, and the absence of a KIT source dependency. Runtime
and database tests live in the deployment module.

## Runtime Files

The assembler creates a generic `CRAWLER_CONFIG.yml`, static crawler mappings,
and empty runtime directories at the workspace root. Put real credentials only
in `crawler/.env`; this file is ignored and must never be committed.

## Development Rule

- Generic crawler framework and database changes should go upstream to OEDS.
- KIT crawler implementations and the temporary compatibility adapter belong
  to `oeds-crawler-pack` until their generic parts are accepted upstream.
- Scheduler and UI changes belong to `oeds-scheduler-ui`.
- Data transformations belong to `oeds-post-scripts`.
- Installation and operations changes belong to `oeds-deployment`.

Every module can be developed and tested in its own checkout. Deployment-level
tests assemble the exact compatible commits from `compatibility.yml`.
